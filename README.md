# Горизонт: демо Nuxt Studio

Демо-сайт вымышленной компании «Горизонт». Он показывает, как контент-менеджер правит сайт прямо в браузере через [Nuxt Studio](https://nuxt.studio), без разработчика. Каждая правка сохраняется коммитом в GitHub, после чего Vercel автоматически пересобирает сайт.

**Стек:** Nuxt 4, Nuxt Content 3, Nuxt UI 4, nuxt-studio, деплой на Vercel.

## Что внутри

| Файл | Что это | Как редактируется в Studio |
|---|---|---|
| `content/index.md` | Главная | Визуальный редактор, блоки PageHero, FeatureGrid, CtaBanner |
| `content/about.md` | О нас | Визуальный редактор, цифры (StatsGrid), команда (TeamGrid) |
| `content/contacts.md` | Контакты | Визуальный редактор, форма заявки |
| `content/blog/*.md` | Статьи блога | Форма (дата, автор, рубрика, обложка, теги) и текст |
| `content/team.yml` | Сотрудники | Форма со списком карточек |
| `content/settings.yml` | Название, меню, телефон, email, соцсети | Форма. Правка в одном месте обновляет шапку, подвал и страницу контактов |
| `public/images/` | Картинки | Медиатека Studio |

Блоки, которые вставляются через `/` в редакторе, лежат в `app/components/content/`. Схемы форм описаны в `content.config.ts`.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Нужен Node.js 22.5 или новее: используется встроенный `node:sqlite`.

В dev-режиме Studio открывается сам, без входа: панель редактора появляется поверх сайта. Правки сразу пишутся в локальные файлы `content/`.

## Деплой на Vercel

1. **Репозиторий.** Запушить проект в GitHub. Репозиторий уже прописан в `studio.repository` в [nuxt.config.ts](nuxt.config.ts): `Lysak-AA/nuxt-studio-demo`.
2. **Vercel.** Импортировать репозиторий: Add New → Project. Настройки по умолчанию подходят, Nuxt определится сам.
3. **GitHub OAuth App.** Создать в GitHub → Settings → Developer settings → OAuth Apps → New:
   - Homepage URL: `https://<проект>.vercel.app`
   - Authorization callback URL: `https://<проект>.vercel.app/__nuxt_studio/auth/github`
4. **Переменные окружения** в Vercel → Settings → Environment Variables (см. [.env.example](.env.example)):
   - `STUDIO_GITHUB_CLIENT_ID`
   - `STUDIO_GITHUB_CLIENT_SECRET`
   - `STUDIO_GITHUB_MODERATORS`: email тех, кому разрешено редактировать (рекомендуется)
5. **Redeploy.** Затем открыть `https://<проект>.vercel.app/_studio` и войти через GitHub.

> В документации Studio переменные называются `NUXT_STUDIO_AUTH_GITHUB_CLIENT_ID` и `..._SECRET`. Но страница `/_studio` в nuxt-studio 1.7 проверяет именно `STUDIO_GITHUB_CLIENT_ID`, поэтому задаём эти имена.

## Сценарий демонстрации (≈10 минут)

Подготовка: открыть сайт и сразу войти в `/_studio`. Во второй вкладке открыть репозиторий на GitHub.

1. **«Это обычный сайт».** Пройтись по главной, «О нас», блогу и контактам.
2. **Правка текста на глазах.** На главной поменять заголовок в блоке PageHero. Превью обновляется мгновенно.
3. **Конструктор из блоков.** В `about.md` набрать `/`, вставить «Призыв к действию» (CtaBanner) и заполнить поля в правой панели.
4. **Одно место — весь сайт.** В `settings.yml` поменять телефон. Он обновится в шапке, подвале и на странице контактов.
5. **Команда.** В `team.yml` загрузить фото сотрудника через медиатеку.
6. **Новая статья.** Создать файл в `blog/`: заполнить форму (дата, рубрика, обложка) и написать текст с блоком Callout.
7. **Публикация.** Нажать Publish. Показать коммит в GitHub и пересборку в Vercel, затем обновлённый сайт через 1–2 минуты.
8. **Для технической части аудитории.** Показать, что это те же Markdown-файлы в Git: история изменений, откат, code review.

Черновики хранятся в браузере до нажатия Publish, поэтому на демо можно спокойно экспериментировать.
